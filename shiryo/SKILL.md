# shiryo — 内容を1枚の資料ページにする

調べたことも決めたことも、チャットの中に置いたままだと誰にも渡せない。**章立てのある1枚のページに落とす**ためのスキル。

## 使うタイミング
- 調べものが長くなって、結論がどこにあるか分からなくなった
- 手順やルールを、人に配れる形で残したい
- 会議・打ち合わせに持っていく資料が要る

図解1枚で足りるなら、このスキルではなく図解のほうが速い。**こちらはページ丸ごと**（見出し・本文・表・年表・出典）を作るときに使う。

## 絶対に守ること

1. 🔴 **器（`template.html`）の CSS は触らない。** `<body>` の「ここから下を差し替える」以降だけ書き換える。
   色・余白・角丸は必ず `var(--...)` 経由で使う（直接 `#fff` などと書かない）
2. 🔴 **使わないブロックは丸ごと消す。** 器には8種類の部品が入っているが、全部使うと「長いだけのページ」に戻る。
   ふだん使うのは **HERO ＋ 本文の章 ＋ 表かタイムラインのどちらか** で足りる
3. 🔴 **元の内容にないことを足さない。** ページの体裁を埋めるために数字・手順・出典を創作しない。
   足りない情報があるときは、書く前に質問する
4. 🔴 **結論を先頭に置く。** `.subhead` を読むだけで用が足りるように書く。前置きから始めない
5. 🔴 **確かなことと、そうでないことを分けて書く。** 伝聞・推測・未確認を断定に混ぜない（下のバッジを使う）

## 部品の選び方

| 内容 | 使う部品 | クラス |
|---|---|---|
| 結論・要点が3つに絞れる | 要約カード | `.grid-3` ＋ `.panel`（1枚だけ `.panel-lift`） |
| 説明が続く本文 | 本文＋補足 | `.prose` ＋ 右に `aside.panel` |
| 3つの段階・手順がある | 段組 | `.steps` |
| やる／やらない・前／後 | 対比 | `.vs` |
| 項目 × 観点で並ぶ | 表 | `.table`（🔴 `.table-scroll` で包む） |
| 時系列がある | 年表 | `.tl`（重要な行にだけ `.is-key`） |
| 画面の場所を指したい | 画面モック | `.mock` |
| 根拠を示したい | 出典 | `.src` |

確度を示すバッジは3種類。色ではなくドットの形で分ける。

- `.badge badge-success` … 裏が取れた・確定
- `.badge badge-own` … 当事者の自己申告
- `.badge badge-check` … 未確認・要検証

## 手順

1. 元の内容から**結論を1〜2文**で抜く → `.subhead` に置く
2. 上の表で部品を選ぶ。**3種類まで**
3. `template.html` をコピーして `〈題材〉.html` を作る
4. `〈…〉` を差し替え、**使わない `<section>` はコメントごと丸ごと消す**
5. `THEME_KEY` をその画面固有の名前に変える（`'shiryo-theme'` のままにしない）
6. ナビの `href` と `<section>` の `id` が一致しているか確かめる
7. ブラウザで開いて確認する。**ダークとライトの両方**をテーマ3択で切り替えて見る。狭い画面（幅375px）でも見る
8. 保存先とファイル名をユーザーに伝える

## やりがちな失敗

- **全部の部品を使う** → 3種類まで。器は選択肢であって、チェックリストではない
- **本文を全幅に伸ばす** → `.prose` で 68ch に止める。1行が長いと読まれない
- **`.is-key` を年表の半分に付ける** → 強調が消える。1〜2割まで
- **表を横に伸ばす** → `.table-scroll` で包む。ページごと横に伸ばさない
- **ナビの項目が10個ある** → 4〜8個まで。多いなら章をまとめる
- **テーマ3択を消す** → 消さない。相手の環境がダークかライトか分からない
- **見出しを体言止めで並べる** → 短くていいので文にする。「〜の課題」より「〜が追いつかない」
